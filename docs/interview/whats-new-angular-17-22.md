# 🆕 What's new in Angular, v17 → v22

Interviewers love *"what changed recently?"*. This page lists the highlights version by version.
The Angular team ships **two majors per year** (roughly May/June and November), with minor releases in between
([Versioning and releases](https://angular.dev/reference/releases)).

**How versions were verified.** Every "introduced / stabilized in vX" claim comes from at least one of:

1. the official **changelog** of `angular/angular` (and `angular/angular-cli` for CLI defaults). Links point to the exact release section;
2. the `@publicApi <version>` / `@deprecated <version>` annotations in the installed **Angular 22.2.4 typings**
   (`node_modules/@angular/*/types/*.d.ts`). `@publicApi 20.0` means "stable since 20.0";
3. an **angular.dev** page.

The official **release blog posts** are linked for each major, but blog.angular.dev blocks automated fetching,
so their content was **not** used as the only proof of anything.
⚠️ marks claims I could not confirm from those sources.

Vocabulary: **experimental** → **developer preview** → **stable**.

## Quick timeline

| Feature | Introduced | Stable / default |
|---|---|---|
| Built-in control flow `@if/@for/@switch` | v17 (dev preview) | ⚠️ stable in v18 (reported by the v18 blog; not listed explicitly in the changelog) |
| `@defer` | v17 | ⚠️ stable in v18 (same remark) |
| `signal` / `computed` | v16 ([changelog](https://github.com/angular/angular/blob/main/CHANGELOG.md#1600-2023-05-03): *"add Angular Signals to the public API"*) | stable in v17 |
| `effect` | v16 | stable in v20 (`@publicApi 20.0`) |
| `input()` / `model()` / `output()` / signal queries | 17.1 / 17.2 / 17.3 / 17.2 | stable in v19 |
| `@let` | 18.1 | stable in v19 |
| Standalone by default (`standalone: true` implicit) | v19 | — |
| `linkedSignal` | v19 (experimental) | stable in v20 |
| `resource` / `rxResource` | v19 (experimental) | stable in v22 |
| `httpResource` | 19.2 (experimental) | stable in v22 |
| `afterRender` → `afterEveryRender` | renamed in v20 | stable in v20 |
| Incremental hydration | v19 (dev preview) | stable in v20, **on by default in v22** |
| Zoneless | v18 (experimental) | dev preview v20, stable 20.2, **default in v21** |
| Vitest as default test runner | v21 (CLI) | — |
| Signal Forms | v21 (experimental) | **stable in v22** |
| OnPush as default change detection | **v22** | — |

## Angular 17 (Nov 2023)

Release blog: [Introducing Angular v17](https://blog.angular.dev/introducing-angular-v17-4d7033312e4b) · [Changelog 17.0.0](https://github.com/angular/angular/blob/main/CHANGELOG.md#1700-2023-11-08)

- **Built-in control flow** `@if`, `@for` (with a mandatory `track`), `@switch`, released as a developer preview, plus a migration schematic
  ([changelog](https://github.com/angular/angular/blob/main/CHANGELOG.md#1700-2023-11-08), [guide](https://angular.dev/guide/templates/control-flow)).
- **Deferrable views `@defer`** with `on viewport / interaction / hover / idle / timer` triggers, and `@placeholder`, `@loading`, `@error`
  ([guide](https://angular.dev/guide/templates/defer)).
- **Signals stable**: the changelog says *"mark core signal APIs as stable"* (`signal`, `computed`; `@publicApi 17.0` on `signal`/`isSignal` in the typings). `effect` stayed in developer preview.
- **New default build system**: `ng new` uses the esbuild-based **`application` builder** with a Vite dev server
  ([CLI changelog 17.0.0](https://github.com/angular/angular-cli/blob/main/CHANGELOG.md#1700-2023-11-08), [build guide](https://angular.dev/tools/cli/build-system-migration)).
- **Standalone by default for new projects** generated by `ng new`, plus `ng new --ssr` and hydration enabled when adding SSR (CLI changelog).
- `provideClientHydration()` stable (`@publicApi 17.0` in typings). Router support for the **View Transitions API** (`withViewTransitions`).
- New docs site **angular.dev** (announced in the release blog).

**Minor releases:**

- 17.1: `input()` signal inputs ([changelog](https://github.com/angular/angular/blob/main/CHANGELOG.md#1710-2024-01-17)).
- 17.2: `model()` and signal queries `viewChild()`/`contentChild()`… ([changelog](https://github.com/angular/angular/blob/main/CHANGELOG.md#1720-2024-02-14)).
- 17.3: `output()`, `outputFromObservable`, `outputToObservable` ([changelog](https://github.com/angular/angular/blob/main/CHANGELOG.md#1730-2024-03-13)).

## Angular 18 (May 2024)

Release blog: [Angular v18 is now available](https://blog.angular.dev/angular-v18-is-now-available-e79d5ac0affe) · [Changelog 18.0.0](https://github.com/angular/angular/blob/main/CHANGELOG.md#1800-2024-05-22)

- **Experimental zoneless** change detection (`provideExperimentalZonelessChangeDetection`, later renamed) ([changelog](https://github.com/angular/angular/blob/main/CHANGELOG.md#1800-2024-05-22)).
- **Fallback content for `<ng-content>`** ([content projection](https://angular.dev/guide/components/content-projection)).
- **Unified control state change events** for forms (`control.events` Observable).
- Router: `redirectTo` can be a **function**, and guards/resolvers can return a **`RedirectCommand`**.
- `HttpClientModule` and related modules **deprecated** in favor of `provideHttpClient()` ([changelog](https://github.com/angular/angular/blob/main/CHANGELOG.md#1800-2024-05-22), [API](https://angular.dev/api/common/http/HttpClientModule)).
- **Event replay** API for SSR (`withEventReplay()`), ⚠️ developer preview at the time (status per the release blog).
- ⚠️ Control flow and `@defer` **promoted to stable**: stated in the v18 release blog, not listed as a changelog entry.
- 18.1: **`@let`** template variables; redesigned `afterRender` phases API ([changelog](https://github.com/angular/angular/blob/main/CHANGELOG.md#1810-2024-07-10)).

## Angular 19 (Nov 2024)

Release blog: [Meet Angular v19](https://blog.angular.dev/meet-angular-v19-7b29dfd05b84) · [Changelog 19.0.0](https://github.com/angular/angular/blob/main/CHANGELOG.md#1900-2024-11-19)

- **`standalone: true` is now the default** for components, directives and pipes. NgModule-based ones must say `standalone: false`. Also a `strictStandalone` compiler flag.
- **Stable**: `input()`, `output()`, `model()`, signal queries (`viewChild`, `contentChild`…), `takeUntilDestroyed`, `outputFromObservable`/`outputToObservable`, and **`@let`** (all `@publicApi 19.0` in typings or listed in the changelog).
- **New (experimental)**: `linkedSignal`, `resource()` and `rxResource()`, and `afterRenderEffect`.
- **`effect()` timing change**: `allowSignalWrites` became a no-op, so signal writes in effects are allowed ([effects guide](https://angular.dev/guide/signals/effect)).
- **Incremental hydration** public API (developer preview): `@defer (hydrate on …)` ([guide](https://angular.dev/guide/incremental-hydration)).
- `provideAppInitializer()` / `provideEnvironmentInitializer()` introduced. `APP_INITIALIZER` / `ENVIRONMENT_INITIALIZER` deprecated *"from v19.0.0"* (typings).
- Templates: `typeof` operator support.
- Migrations to signal inputs, signal queries and `output()` ([migrations](https://angular.dev/reference/migrations)).
- 19.2: experimental **`httpResource`**, streaming resources, untagged template literals in templates ([changelog](https://github.com/angular/angular/blob/main/CHANGELOG.md#1920-2025-02-26)).

## Angular 20 (May 2025)

Release blog: [Announcing Angular v20](https://blog.angular.dev/announcing-angular-v20-b5c9c06cf301) · [Changelog 20.0.0](https://github.com/angular/angular/blob/main/CHANGELOG.md#2000-2025-05-28)

- **Signals fully stable**: `effect`, `linkedSignal`, `toSignal`, `toObservable` (all `@publicApi 20.0`).
- **`afterRender` renamed `afterEveryRender`** and stabilized, together with `afterNextRender` ([API](https://angular.dev/api/core/afterEveryRender)).
- **Zoneless → developer preview**. `provideExperimentalZonelessChangeDetection` renamed `provideZonelessChangeDetection`.
- **Incremental hydration stable** (`withIncrementalHydration`, `@publicApi 20.0`).
- **`NgIf`, `NgFor`, `NgSwitch` deprecated** in favor of control flow (`@deprecated 20.0` in typings).
- `PendingTasks` stable. `TestBed.flushEffects()` removed: use `TestBed.tick()`.
- Template expressions: exponentiation `**`, `void`, `in` operator, tagged template literals.
- **New style guide & CLI file naming**: `ng generate` no longer adds the `.component`/`.service`/`.directive` suffix (e.g. `user-profile.ts`, class `UserProfile`),
  and uses a dash type separator for guards, pipes, etc. (`auth-guard.ts`). An update migration keeps the old behavior for existing projects
  ([CLI changelog 20.0.0](https://github.com/angular/angular-cli/blob/main/CHANGELOG.md#2000-2025-05-28), [style guide](https://angular.dev/style-guide)).
- 20.1: `EnvironmentInjector.destroyed`; `loadComponent`/`loadChildren` run in the route's injection context ([changelog](https://github.com/angular/angular/blob/main/CHANGELOG.md#2010-2025-07-09)).
- 20.2: **zoneless promoted to stable** (`provideZonelessChangeDetection` is `@publicApi 20.2`). **`animate.enter` / `animate.leave`**. The `@Component({ animations: [...] })` metadata (the `@angular/animations` DSL) is `@deprecated 20.2` (*"Intent to remove in v23"*). `Router.currentNavigation` signal
  ([changelog](https://github.com/angular/angular/blob/main/CHANGELOG.md#2020-2025-08-20), [animations guide](https://angular.dev/guide/animations)).

## Angular 21 (Nov 2025)

Release blog: [Angular v21 is now available](https://blog.angular.dev/angular-v21-is-now-available-57946c34f14b) (official short link from [angular.dev/events/v21](https://angular.dev/events/v21)) · [Changelog 21.0.0](https://github.com/angular/angular/blob/main/CHANGELOG.md#2100-2025-11-19)

- **Zoneless by default**: new apps are zoneless (CLI: *"Applications are zoneless by default"*), and core no longer provides a zone-based scheduler unless you add `provideZoneChangeDetection()`
  ([CLI changelog 21.0.0](https://github.com/angular/angular-cli/blob/main/CHANGELOG.md#2100-2025-11-19), [zoneless guide](https://angular.dev/guide/zoneless): *"Zoneless is the default in Angular v21+"*).
- **Vitest is the default test runner** for new projects (*"configure Vitest for new projects and allow runner choice"*), plus a `jasmine-to-vitest` refactor schematic
  ([CLI changelog](https://github.com/angular/angular-cli/blob/main/CHANGELOG.md#2100-2025-11-19), [testing guide](https://angular.dev/guide/testing)).
- **Signal Forms (experimental)** in `@angular/forms/signals`, with a `debounce()` rule ([changelog](https://github.com/angular/angular/blob/main/CHANGELOG.md#2100-2025-11-19)).
- **`HttpClient` injectable by default**: *"HttpClient is available for injection by default in Angular v21 and later"* ([setup guide](https://angular.dev/guide/http/setup)). ⚠️ I didn't find the matching changelog entry.
- Router: experimental support for the browser **Navigation API**.
- TypeScript < 5.9 dropped. `NgModuleFactory` removed.
- ⚠️ **Angular Aria** (headless accessible components) launched around v21 as a preview. The exact status at v21 isn't in the `angular/angular` changelog (it lives in another repo), so this is unconfirmed. See [Angular Aria](https://angular.dev/guide/aria/overview).
- 21.1: the **`[formField]`** directive for Signal Forms ([changelog](https://github.com/angular/angular/blob/main/CHANGELOG.md#2110-2026-01-14)).
- 21.2: the `form` directive, `SignalFormControl` for Reactive Forms interop, parse errors, and resource composition via snapshots ([changelog](https://github.com/angular/angular/blob/main/CHANGELOG.md#2120-2026-02-25)).

## Angular 22 (Jun 2026)

Release blog: [Announcing Angular v22](https://blog.angular.dev/announcing-angular-v22-c52bb83a4664) (official short link from [angular.dev/events/v22](https://angular.dev/events/v22)) · [Changelog 22.0.0](https://github.com/angular/angular/blob/main/CHANGELOG.md#2200-2026-06-03)

**Stabilizations.** The [v22 event page](https://angular.dev/events/v22) says: *"Signal Forms, Asynchronous Signals, and Angular Aria are now stable"*.

- **Signal Forms stable**: changelog *"graduate signal forms APIs to public API"*, with `form`, `FormField`, `FormRoot`, the validators and `submit` all `@publicApi 22.0`. New in 22.0: `reloadValidation()`, `FieldState.getError()`, and a `debounce` option on `validateAsync`/`validateHttp` ([guide](https://angular.dev/guide/forms/signals/overview)).
- **`resource`, `rxResource`, `httpResource` stable** (`@publicApi 22.0`). New `id` option for SSR caching of resources ([resource guide](https://angular.dev/guide/signals/resource)).

**Breaking and behavior changes:**

- **OnPush is the default**: *"Component with undefined `changeDetection` property are now `OnPush` by default. Specify `changeDetection: ChangeDetectionStrategy.Eager` to keep the previous behavior."*
  `ChangeDetectionStrategy.Default` becomes a deprecated alias of `Eager`, and an `ng update` migration adds `Eager` where needed ([skipping subtrees](https://angular.dev/best-practices/skipping-subtrees)).
- **`FetchBackend` is the default** HTTP backend. `withFetch()` is deprecated, and `withXhr()` keeps XHR (needed for upload progress). `reportProgress` is deprecated in favor of `reportUploadProgress`/`reportDownloadProgress` ([setup guide](https://angular.dev/guide/http/setup)).
- **Incremental hydration on by default** with `provideClientHydration()`. `withIncrementalHydration()` is deprecated and `withNoIncrementalHydration()` is new (typings).
- Templates: optional chaining `?.` now returns `undefined` like TypeScript, safe navigation narrows nullables, comments are allowed inside element tags, and `data-` attributes no longer bind inputs or outputs.
  Elements matching several component selectors now fail at compile time (NG8023).
- ⚠️ `strictTemplates` enabled by default. The changelog shows *"add strictTemplates to tsconfig during ng update"* and a 22.1 fix *"account for strictTemplates being enabled by default"*, but I couldn't confirm the exact `ng new` default from an official doc page.
- Router: `paramsInheritanceStrategy` defaults to `'always'`. `CanMatchFn` gets a required third `currentSnapshot` parameter. `provideRoutes()` is removed.
- Removed: `ComponentFactoryResolver`/`ComponentFactory`, `createNgModuleRef`, `ChangeDetectorRef.checkNoChanges`, and the Hammer.js integration.
- TypeScript **6.0+ required**. Node.js 26 supported.

**New APIs:**

- **`@Service()` decorator**: an auto-provided service, shorthand for `@Injectable({ providedIn: 'root' })`, `inject()`-only ([API](https://angular.dev/api/core/Service), [guide](https://angular.dev/guide/di/creating-and-using-services)).
- **`injectAsync()`**: lazy-load a service via dynamic `import()`, with prefetch triggers such as `onIdle` ([API](https://angular.dev/api/core/injectAsync)).
- **`debounced()`** signals, `@experimental 22.0` in the typings ([API](https://angular.dev/api/core/debounced)).
- `@defer (on idle(…))` accepts a timeout, and the idle service can be customized. `TestBed.getLastFixture()`. Router `withComponentInputBinding({ queryParams, unmatchedInputBehavior })` and `RouterLink` `browserUrl`.
- Tooling: an Angular **CLI `migrate-karma-to-vitest`** migration ([CLI changelog 22.0.0](https://github.com/angular/angular-cli/blob/main/CHANGELOG.md#2200-2026-06-03)). AI tooling: WebMCP experiments and agent skills ([AI docs](https://angular.dev/ai)).

**Minor releases:**

- 22.1: `linkedSignal` custom `set` option, a migration from `@Injectable` to `@Service`, and **JSONP deprecated** (`@deprecated 22.1`) ([changelog](https://github.com/angular/angular/blob/main/CHANGELOG.md#2210-2026-07-29)).
- 22.2: **`withAutoCleanupInjectors()`** stable (destroys unused route injectors), throwing a `RedirectCommand` triggers a redirect, and router resources are in the public API ([changelog](https://github.com/angular/angular/blob/main/CHANGELOG.md#2220-2026-09-23)).

## 🎯 How to talk about this in an interview

> 💡 **Interview tip:** Don't recite a list. Tell the story. *"Since v16, Angular has been moving to a **signal-based, zoneless,
> standalone** model: signals (v16–17), signal component APIs (v17–19), zoneless (v18 → default in v21), OnPush by
> default (v22), and async and forms on signals (resource and Signal Forms stable in v22). Legacy APIs (NgModules, zone.js,
> `*ngIf`, `@Input`) still work, and `ng update` migrations help move them over."*
